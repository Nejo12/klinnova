## 1. Purpose

Create a controlled, comparable and funding-safe package for collecting **non-binding provider quotations** for the highest-priority specialist blocks:

- C01 — legal/privacy/employment-platform specialist review;
- C03 — UX/accessibility/user-research specialist support;
- C04 — security/technical assurance;
- C05 — bounded external engineering support.

The package is designed to improve application evidence quality without accidentally creating a contract, purchase commitment or funded-project start.

## 2. Governing rule

A quotation request must be framed as **application-planning evidence only**.

Each request should state clearly that:

1. Klinnova is preparing a funding application;
2. the request is for a **non-binding estimate/quotation**;
3. no engagement, purchase order or service start is being placed;
4. any later engagement would require separate written Founder approval;
5. any later work would start only after the applicable funding/project-start boundary has been cleared;
6. the provider should not begin work, reserve paid capacity, issue an invoice or incur chargeable effort merely because the quotation was requested.

## 3. Minimum quotation fields

Every provider response should ideally contain:

| Field | Required target |
|---|---|
| Provider legal/business name | yes |
| Provider contact | yes |
| Relevant qualification/specialism | yes where applicable |
| Scope / deliverables | yes |
| Estimated hours or days | yes |
| Hourly/day rate or fixed-price basis | yes |
| Net amount | yes |
| VAT rate / VAT amount | yes where applicable |
| Gross amount | yes |
| Estimated delivery duration | yes |
| Earliest possible start | useful, but no reservation |
| Quotation validity | useful |
| Assumptions / exclusions | yes |
| Statement that quotation is non-binding | preferred |

A provider does not need to use Klinnova's wording exactly. The evidence should nevertheless be clear enough to show amount basis, scope and future timing.

## 4. Contact safety rules

Before any request is actually sent:

- Founder must explicitly authorize provider contact;
- use a business contact channel, preferably `support@klinnova.com`;
- do not send sensitive personal documents;
- do not send repository secrets, credentials, database exports or production customer data;
- do not accept terms merely to obtain a price;
- do not click an "order", "book", "confirm appointment", "accept quote" or equivalent action without separate authorization;
- do not pay for a discovery session where free/non-binding quotation preparation is sufficient;
- if a provider requires paid discovery before quoting, record that as a limitation and seek alternatives before committing.

## 6. C01 — legal/privacy/employment-platform specialist review

### 6.1 Planning ceiling

Current working amount: **EUR 4,000**.

This is a planning ceiling, not a target that a provider should be encouraged to match.

### 6.2 Provider profile

Prefer a German-qualified lawyer/law firm or appropriately qualified specialist with demonstrable experience in several of the following:

- digital-platform / IT law;
- data protection / GDPR;
- DDG information duties;
- online terms / AGB;
- recruitment/employment-platform law;
- AGG/discrimination risk in recruitment flows;
- intermediary/platform operating models.

### 6.3 Request scope

Ask for a bounded review of the future operational phase, potentially covering:

1. operator/imprint and applicable information duties;
2. privacy notice and data-processing disclosures against actual intended Klinnova processing;
3. employer/candidate terms or platform rules where legally appropriate;
4. employment-platform/intermediary boundary issues relevant to Klinnova;
5. AGG/discrimination considerations in vacancy, matching and application flows;
6. high-level review of trust/safety and account-policy wording where legally material;
7. prioritized written findings and recommended amendments;
8. one bounded follow-up/review round if appropriate.

Do **not** ask for a blanket statement that Klinnova is "fully GDPR compliant" or "legally certified".

## 7. C03 — UX/accessibility/user-research specialist support

### 7.1 Planning ceiling

Current working amount: **EUR 3,500**.

### 7.2 Provider profile

Prefer an independent UX/accessibility specialist or small agency able to combine or clearly separate:

- expert UX review;
- responsive/mobile usability;
- WCAG-oriented manual accessibility assessment;
- candidate/employer user research planning;
- synthesis and prioritized recommendations.

### 7.3 Request scope

Possible bounded package:

1. expert review of candidate and employer core journeys;
2. mobile/responsive usability review;
3. manual accessibility assessment of critical flows against relevant WCAG criteria;
4. research plan for a small number of legitimate candidate/employer sessions;
5. optional moderation or analysis support for those sessions after external beta is permitted;
6. findings report prioritized by severity/value;
7. one bounded remediation-review round.

Participant recruitment costs should be separated if relevant.

## 8. C04 — security/technical assurance

### 8.1 Planning ceiling

Current working amount: **EUR 3,500**.

### 8.2 Provider profile

Prefer an independent application-security specialist or small security firm with experience in modern web applications and APIs.

Relevant competence may include:

- web application penetration testing;
- API testing;
- authentication/authorization testing;
- OWASP Top 10;
- SaaS/cloud configuration review;
- remediation verification.

### 8.3 Request scope

The request should deliberately avoid describing C04 as an unlimited full-scope enterprise pentest.

Indicative bounded scope:

1. agreed critical web-application flows;
2. authentication and session handling;
3. candidate/employer role and authorization boundaries;
4. selected API/server workflows;
5. common OWASP Top 10 classes;
6. targeted configuration/security review where material;
7. prioritized written findings with severity and remediation guidance;
8. optional one-time bounded retest of corrected high/critical findings.

Provider should identify assumptions about test accounts, environments and exclusions.

## 9. C05 — bounded external engineering support

### 9.1 Planning ceiling

Current working amount: **EUR 7,000**.

### 9.2 Core control

The Founder remains the primary developer. C05 must therefore **not** be framed as outsourcing ordinary Founder development work.

The strongest quotation scope is specialist/capacity support for future, clearly bounded tasks.

### 9.3 Suitable provider profiles

Depending on the work package:

- senior full-stack/backend engineer;
- Supabase/PostgreSQL/RLS specialist;
- test-automation/E2E specialist;
- deployment/reliability specialist;
- senior engineer for bounded security/accessibility remediation.

Avoid a vague "build the platform" quotation.

### 9.4 Work-package architecture

A quote may cover one or more separately priced future packages, for example:

**WP-A — backend / authorization hardening**
- review and remediation of selected authorization/data-access boundaries;
- RLS/data-layer improvements where evidence requires them;
- documented tests.

**WP-B — critical E2E/test engineering**
- high-value candidate/employer flows;
- regression coverage for funded-phase changes;
- CI reliability around those flows.

**WP-C — specialist remediation capacity**
- bounded implementation tasks arising from independent security, accessibility or legal reviews;
- only after those findings exist and the tasks are separately approved.

**WP-D — deployment/reliability support**
- future production-delivery reliability work demonstrably required for the funded phase.

Historical MVP work, routine maintenance and generic frontend backlog are excluded.

## 11. Evidence-storage rule

Provider quotations may contain personal contact details, signatures, bank details or other non-public information.

Therefore:

- do not commit sensitive provider PDFs/emails to the public repository;
- repository records may store provider name, evidence date, amount basis, scope summary and a private evidence locator/reference;
- original quotation files should remain in an appropriate private Founder-controlled storage location;
- redact unnecessary personal information if an application attachment requires sharing beyond the intended recipient.

## 12. Quote collection sequence

Recommended order once Founder explicitly authorizes provider contact:

1. **C01 legal/privacy** — highest substantive application/legal dependency;
2. **C04 security** — well-bounded and easy to compare across providers;
3. **C03 UX/accessibility** — clarify whether research participant costs are separate;
4. **C05 engineering** — request work-package estimates rather than a generic development retainer.

For each block, target at least one useful non-binding quote. Multiple comparable quotes are beneficial where practical, but this document does not claim that the programme mandates a specific number of quotations.

## 13. Stop conditions during quote collection

Stop and return to Founder for a decision if a provider:

- requires signature of terms before giving an estimate;
- requires a paid discovery engagement;
- sends an order confirmation rather than a quotation;
- requests production credentials or sensitive data merely to quote;
- proposes starting immediately;
- requires a deposit or reservation fee;
- materially changes the intended scope;
- presents a cost far outside the planning envelope and the difference would alter the project architecture.

## 14. What a quotation does not prove

A quotation does **not** by itself prove:

- final GründungsBONUS Plus eligibility;
- that VAT is an eligible cost;
- that the provider will ultimately be selected;
- that the quoted service may start before a funding decision;
- that the final application must use the quoted amount;
- that the EUR 40,000 planning ceiling must be preserved.

It is evidence of a plausible future market cost for a defined scope.
