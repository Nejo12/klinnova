# GründungsBONUS Plus — C05 External Engineering Support Evidence

Status: WORKING EVIDENCE RECORD — NON-BINDING MARKET EVIDENCE ONLY

## 1. Purpose

This document evaluates the current EUR 7,000 planning allocation for bounded external engineering support in the Klinnova GründungsBONUS Plus application track.

It does not authorize procurement, contracting, payment, hiring, production changes or application submission.

The purpose is to determine whether the C05 amount is commercially plausible and what kind of work can credibly sit behind it without duplicating the Founder’s own core development contribution.

## 2. Current planning line

C05 planning allocation:

- Target amount: EUR 7,000
- Category: targeted external development / engineering support
- Funding-plan status: provisional
- Evidence status before this review: planning assumption only

## 3. Current public market evidence

Current 2026 Malt tariff data for experienced ReactJS freelancers in Germany reports an average daily rate of approximately EUR 673–674.

For Berlin, the current ReactJS benchmark shown by Malt is approximately EUR 653/day, with limited representativeness because the city sample is small.

At these benchmarks:

- EUR 7,000 / EUR 674 ≈ 10.4 days
- EUR 7,000 / EUR 653 ≈ 10.7 days

Therefore the current C05 allocation corresponds approximately to ten to eleven experienced freelance engineering days at current public market rates.

This supports commercial plausibility of the EUR 7,000 ceiling.

## 4. Important Founder-boundary rule

Klinnova is Founder-built and the Founder already provides the core software-development capability.

C05 must therefore not be framed as paying an external developer to perform the Founder’s ordinary baseline product-development work.

The stronger funding rationale is that C05 finances bounded specialist or capacity support that accelerates or de-risks the funded future project while preserving Founder ownership of the core product.

## 5. Appropriate C05 scope candidates

Potentially defensible external engineering scope includes:

### 5.1 Backend / data-layer specialist work

Examples:

- complex Supabase/PostgreSQL query or policy review;
- RLS/security-policy implementation support;
- data-integrity and concurrency review;
- performance-sensitive query/index review;
- migration or schema-review support where required by the funded project.

### 5.2 Authentication / authorization specialist support

Examples:

- role-boundary review;
- candidate/employer/operator authorization review;
- session and recovery-flow hardening;
- abuse-path remediation;
- implementation of findings from a security assessment.

### 5.3 Test engineering / quality assurance

Examples:

- targeted end-to-end coverage for funded market-entry workflows;
- browser/device regression automation;
- accessibility regression tooling;
- reliability testing of employer/candidate application flows;
- flaky-test stabilization for critical funded-project workflows.

### 5.4 Delivery / infrastructure engineering

Examples:

- CI/CD hardening;
- deployment-safety improvements;
- observability integration after privacy clearance;
- environment/configuration reliability;
- backup/recovery implementation work if required.

### 5.5 Specialist implementation arising from legal/security/UX findings

Examples:

- remediation of verified accessibility findings;
- implementation required by qualified legal/privacy review;
- implementation required by focused security assurance;
- technically complex changes outside efficient Founder capacity.

This is a particularly strong rationale because the work would be traceable to independently identified funded-project requirements rather than generic feature development.

## 6. Weak or inappropriate C05 scope

The following should not be used to justify C05 without a stronger project-specific reason:

- generic React component development that the Founder routinely performs;
- ordinary page styling;
- routine bug fixing;
- speculative features without connection to funded milestones;
- historical MVP work;
- work already completed before the relevant funding boundary;
- Founder labour disguised as third-party expenditure;
- permanent outsourced product ownership.

## 7. Recommended bounded work-package architecture

A credible EUR 7,000 package could be structured as one or more fixed work packages rather than an open-ended contractor retainer.

Illustrative architecture only:

### Package A — Backend / authorization hardening

Indicative effort:

- 3–4 specialist days

Possible outputs:

- review of critical data-access paths;
- identified authorization weaknesses;
- bounded remediation implementation;
- documented handover.

### Package B — Critical workflow test engineering

Indicative effort:

- 3–4 specialist days

Possible outputs:

- high-value E2E test cases;
- regression coverage for funded workflows;
- reliability fixes for critical test paths.

### Package C — Specialist remediation / delivery support

Indicative effort:

- 3–4 specialist days

Possible outputs:

- remediation arising from accessibility/security/legal findings;
- CI/deployment/observability implementation;
- technical handover.

Total illustrative capacity:

- approximately 9–12 days depending on provider rate and final scope.

This aligns reasonably with the public market-rate evidence.

## 12. Key conclusion

Current public 2026 market evidence supports EUR 7,000 as commercially plausible for approximately ten to eleven experienced freelance engineering days.

The material application risk is not price plausibility. It is scope duplication.

The final C05 evidence must therefore show that external engineering support is:

1. bounded;
2. specialist or capacity-driven;
3. tied to the future funded project;
4. not historical MVP work;
5. not a substitute for ordinary Founder development;
6. evidenced by a non-binding Klinnova-specific quote before final application freeze.

Until that evidence is collected, C05 remains provisional and no provider engagement is authorized.
